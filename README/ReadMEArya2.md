## 1. Exactly what was implemented

Two separate branches were added after the existing classification baseline:

```text
Existing fold-specific WideResNet checkpoint
    + the exact fold_manifest.csv used to train it
    + the original images selected by that manifest
        -> Restore the recorded preprocessing
        -> Freeze the backbone and use evaluation mode
        -> Extract pooled features: [N, 2048]
             |
             +-- Metric branch
             |     -> Independent Linear(2048, 64) projection
             |     -> Contrastive training using training-image pairs
             |     -> Save projected training images as the KNN bank
             |     -> Classify validation images as Control / Parkinson / Unknown
             |
             +-- RBF branch
                   -> Independent Linear(2048, 64) projection
                   -> Learn Control and Parkinson centres
                   -> Train known/rejected-example margin loss
                   -> Calculate L1 or Euclidean L2 distances
                   -> Accept the nearest known class or reject as Unknown
```

Both branches include training, a resumable stage checkpoint, independent evaluation, image prediction tables, reports and source/configuration checks.

The RBF branch **does not require a trained contrastive projection**. It starts its own projection from the same type of frozen baseline features. These are alternative experiments, not one mandatory contrastive-then-RBF sequence.

B4 reads the baseline checkpoint and manifest-selected images directly. It does not consume the feature CSV generated by the earlier `extract_embeddings.py`. Extracted pooled features are held in memory for the current invocation and are not a persistent all-fold cache.

## 3. Input contracts and backbone behavior

The source checkpoint must satisfy these checks:

| Item | Required contract |
| --- | --- |
| Architecture | Current separated `wide_resnet50_2` baseline |
| Representation | 2048-D pooled features; no legacy joint projection |
| Labels | `label_source="consensus"`; three classes in the order `control`, `parkinson`, `unknown` |
| Fold | A development fold ID from 1 through 25, matching the requested run |
| Manifest | File SHA-256 exactly matches the baseline's saved manifest hash |
| Preprocessing | Supported configuration, matching configuration hash and image size |
| Source ownership | A trusted baseline trained without the evaluated participants; shape/metadata checks cannot establish the history of arbitrary external weights |

The roadmap's reported sequence starts with focal classification. A CE baseline is also accepted for a separately identified comparison; the source loss and epoch are recorded. B4 does not retrain that classifier or download ImageNet weights when restoring its source backbone.

During feature extraction, all backbone parameters have `requires_grad=False` and the model is in evaluation mode. B4 optimization updates the projection and, for RBF, the centres. The source classifier head is not used to make B4 decisions.

The baseline's recorded image size is restored; with the standard input configuration the shapes are:

```text
Images:             float32[B, 3, 224, 224]
Pooled features:    float32[N, 2048]
Embeddings:         float32[N, 64]       # default embedding dimension
RBF distances:      float32[N, 2]        # Control and Parkinson
Expert targets:     int64[N]            # Control=0, Parkinson=1, Unknown=2
```

The scripts accept alternate manifest/data locations through `--manifest` and `--root`. They reuse the existing dataset's eligibility, participant and duplicate-content checks.

## 4. Metric branch: projection, pairs, loss and KNN

The default projection is one linear layer, with a bias, from 2048 to 64 dimensions. There is no hidden layer or activation. `--embedding-dim` changes its output dimension; `--normalize` enables an additional L2 normalization and is recorded as a separate experimental choice.

Training pairs are constructed from the training fold only:

- Consider unordered image pairs once; do not pair an image with itself.
- Images with the same expert label form positive pairs. If that class has multiple participants, positives use different participants.
- If a class has only one participant, same-participant positives are allowed when multiple drawings exist; this fallback is logged. A class with only one drawing cannot supply a positive pair.
- Different expert labels form negative pairs. These can include different drawings from the same participant.
- The run requires at least one positive and one negative pair. Missing classes, participant support and fallback cases are recorded.

The implemented contrastive convention is:

```text
d = Euclidean distance between two projected embeddings
positive_loss = d²
negative_loss = max(margin - d, 0)²
loss = mean(mean_positive_loss, mean_negative_loss)
```

The final mean includes only nonempty pair groups. The loss uses Euclidean distance even when `--distance l1` is selected for the subsequent KNN classifier.

One epoch is one full-training-fold optimizer update, rather than an image minibatch sweep. This is intended for the current small dataset and keeps valid pairs available; pair count grows quadratically with the training-image count.

After fitting the projection, KNN stores only projected training drawings and their expert labels. Validation queries never enter that bank. Supported choices are L1/L2 neighbor distance and uniform/inverse-distance voting. Class-vote ties produce Unknown. Exact-zero neighbors receive all the voting weight in distance-weighted voting when present among the selected k neighbors. Equal-distance neighbor ordering is deterministic by drawing ID.

Unknown is a third learned comparison class in this branch. KNN vote fractions are exported as `vote_control`, `vote_parkinson` and `vote_unknown`; they are not calibrated probabilities.

## 5. RBF branch: known classes and rejected-origin groups

RBF has its own projection and two trainable centres: Control and Parkinson. Their initial positions are the means of the corresponding projected training-class features. Both known expert classes must occur in the training fold.

The distance definitions are:

```text
L1: sum(abs(z - centre))
L2: Euclidean norm(z - centre), not squared Euclidean distance
```

The reference loss implemented from the roadmap is:

```text
known_loss = mean_known(d_correct + max(known_margin - d_other, 0))
reject_loss(group) = mean_group(sum_c max(reject_margin - d_c, 0))
total_loss = known_loss + beta * mean(nonempty reject-group losses)
```

Known targets use expert Control/Parkinson, even when the recorded clinical label disagrees. Expert-Unknown examples are divided into two rejected training groups by recorded clinical origin: Control and Parkinson.

The two nonempty reject-group means receive equal weight regardless of their image counts. Missing groups are reported and do not create NaNs. An Unknown training image with missing/invalid clinical origin raises an error instead of silently disappearing from the objective.

Clinical origin is used to construct the rejected training groups. RBF inference takes features and distances; clinical origin is not an input to the decision rule. Focal loss belongs to the earlier baseline stage and is not multiplied into this margin objective.

This head is a restricted learned-centre implementation. The original thesis's modified loss and complete stage schedule were unavailable; this is not a claim to have recovered its original implementation or the more general affine Deep-RBF head.

## 6. Rejection rule and boundary cases

The saved RBF configuration applies these rules in order:

```text
If min(d_control, d_parkinson) > distance_threshold:
    Unknown / far_from_known_classes
Else if d_control == d_parkinson:
    Unknown / equal_distance_tie
Else if abs(d_control - d_parkinson) < gap_threshold:
    Unknown / ambiguous_distance_gap
Else:
    nearest known class / accepted
```

Distance-threshold equality is accepted if no later rejection rule applies. Gap-threshold equality is accepted unless there is an exact distance tie. The gap rule is global. Exact ties remain Unknown even when the configured gap threshold is zero.

`--distance-threshold` and `--gap-threshold` must be supplied explicitly for RBF training. They are saved with the stage. Evaluation does not provide an override. Thresholds, margins and beta must be chosen through development experiments; the example command values are not validated thesis settings. L1 and L2 require separate selection because their scales differ.

## 7. Checkpoints, resume, provenance and test isolation

Each branch/fold has its own `last.pt`. It saves the stage model, optimizer, Torch RNG state, epoch, loss history, configuration/digest, source-baseline path/hash, exact manifest hash, preprocessing and training identities. The metric stage also saves the training embedding bank and its labels/identities.

The checkpoint references the original frozen baseline rather than duplicating its weights. Preserve that file. If it moves, evaluation accepts `--baseline-checkpoint` for a relocated byte-identical copy and checks its hash.

`--resume` restores the state from the selected output directory. The configuration, source identity and training drawing membership must match. `--epochs` is the total budget and can increase on resume. A fresh run refuses a nonempty output directory.

Training requests only train and validation features. The script uses a fixed final epoch budget; it does not choose a best epoch or tune settings on test data. Evaluation checks the saved training identities and KNN bank against the exact manifest and rejects evaluation-participant overlap.

`eval_representation.py --split test` requires `--confirm-heldout-test`. That explicit unlock is for the later frozen final protocol. Fold 22 is supported with an empty validation table and null metrics, rather than an invented validation score.

## 8. How to run it

Run from the repository root in the existing environment:

```bash
source .venv/bin/activate
python -m pytest -q tests/test_representation_models.py tests/test_representation_pipeline.py
```

A real-data run first needs a valid fold-specific baseline checkpoint. At the implementation handoff, none was present in this checkout. After finishing the baseline stage, replace the path below with its actual final checkpoint path:

```bash
BASELINE="/absolute/path/to/fold01_focal_last.pt"

python train_representation.py --branch metric --fold-id 1 \
  --baseline-checkpoint "$BASELINE" \
  --epochs 30 --embedding-dim 64 --margin 1.0 \
  --knn-k 3 --distance l2 --knn-weighting uniform \
  --output-dir outputs/representations/metric_fold01
```

For a separate RBF experiment:

```bash
python train_representation.py --branch rbf --fold-id 1 \
  --baseline-checkpoint "$BASELINE" \
  --distance l1 --epochs 30 --embedding-dim 64 \
  --known-margin 1.0 --reject-margin 1.0 --beta 1.0 \
  --distance-threshold 1.0 --gap-threshold 0.1 \
  --output-dir outputs/representations/rbf_l1_fold01
```

These are runnable command forms once the baseline path is supplied; the numeric values are illustrative development settings. Repeat with L2 in its own directory for that comparison. Repeat the same training command with `--resume` to continue its stage.

Independent validation reload:

```bash
python eval_representation.py --checkpoint outputs/representations/metric_fold01/last.pt \
  --split val --output-dir outputs/representations/metric_fold01/reloaded_val
```

Use the RBF checkpoint path to reload that branch. Additional settings include `--lr`, `--weight-decay`, `--seed`, `--device` and `--feature-batch-size`; see each command's `--help` and the detailed B4 guide.

## 9. Output files and reporting behavior

| Output | Contents |
| --- | --- |
| `last.pt` | Stage-specific training state and provenance; metric branch also includes its training-only KNN bank |
| `val_predictions.csv` | One row per held-out development image with drawing/participant IDs, expert reference, clinical metadata, prediction, decision reason, stage/epoch/config identity and baseline/manifest/stage-checkpoint hashes |
| Metric prediction columns | Three KNN vote fractions |
| RBF prediction columns | Control and Parkinson distances |
| `val_report.json` | Image confusion matrix, class supports, accuracy, F1 variants, per-class precision/recall/F1, coverage, rejection fraction, accepted accuracy, all-case PD recall, training diagnostics and fidelity note |

Evaluation exports analogous prediction/report files for its requested split. Empty validation has a header-only CSV and null metrics. Accepted accuracy is null when no decisions are accepted. Undefined per-class precision/recall are null. Rejected true-PD cases remain in the all-case PD recall denominator. All-class macro-F1 retains the baseline's zero contribution for absent classes, with a present-class variant also available.

The reference for these metrics is the expert image label, including Unknown. The presence of clinical metadata in a prediction row does not make the report a clinical-reference performance report. For KNN, the coverage summary counts predictions outside the Unknown class; it is not an RBF-distance acceptance calculation.

These output files use a B4 schema. The existing baseline `aggregate_validation.py` does not automatically pool them. Participant decisions and ensemble voting are not added by this phase.

## 10. Verification actually performed

The initial representation verification run passed **24 tests**; the subsequent audit added numerical-gradient, learning-behavior and inference-label-isolation checks, bringing this subset to **34 tests**. The lifecycle cases include the metric branch, RBF L1 and RBF L2.

| Area | Checked behavior |
| --- | --- |
| Projection and pairs | Output dimensions, optional normalization, cross-participant positives and documented minority fallback |
| Contrastive loss | Hand-calculated value, attraction/repulsion gradient directions and finite empty/zero-distance behavior |
| KNN | L1/L2 neighbor differences, vote ties, exact-zero distance weighting and invalid k |
| RBF loss/head | Distance units, balanced reject-origin means, known/rejected gradient directions, missing groups, invalid origins and finite projection/centre gradients |
| Rejection | Far-first priority, threshold equalities, exact ties and invalid thresholds |
| Reporting | Rejections retained in all-case PD recall, coverage and undefined accepted/precision denominators |
| Lifecycle | Train/resume versus continuous training, independent reload reproducing prediction rows, and frozen source/manifest preservation |
| Isolation and provenance | Wrong fold/config/hash rejected, test lock, evaluation participant overlap rejected, substituted KNN bank rows rejected and empty validation handled |

Lifecycle tests use synthetic images and a small stand-in backbone. One case deletes the test image before training to verify that the run does not need test pixels. These tests establish software behavior, not classification quality on the research data.

The initial broader-suite run found an outdated model double in `tests/test_preprocessing_entrypoints.py`. The audit updated that test to exercise the actual epoch/prediction/reload paths with a compatible small model and the final checkpoint. The current full suite passes **102 tests**; data-policy reconciliation and real-data model validation remain separate requirements.
