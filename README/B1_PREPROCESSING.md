# B1: preprocessing and data loading

This implements the input part of roadmap package B1. The WideResNet/model-output work is outside this change. The existing model files and A1–A3 label/fold generation rules are unchanged.

## Project layout

The implementation follows the supplied `config/`, `model/`, `data/`, `utils/` structure:

- `config/data_config.py`: dataset paths, input size, normalization constants and serializable preprocessing settings.
- `data/dataloader.py`: image preprocessing, tensor validation, `SpiralDataset` and `make_loader`.
- `utils/image_review.py`: development-only before/after grid and source provenance.
- `utils/check_inputs.py`: runnable model-free B1 input check.
- `train.py` and `eval.py`: consume the loader and record/restore its input configuration.

`data/dataset.py` only re-exports the original public names for compatibility with existing callers. The unused top-level `preprocessing/` folder has been removed; preprocessing runs inside `data/dataloader.py`.

## Method: spiral-full-frame-v1

The first baseline follows roadmap page 8:

1. Decode the PNG and composite its alpha channel onto white, then convert to RGB. RGB, RGBA, grayscale and palette inputs are supported.
2. Fit the **complete image** into a 224 × 224 square using uniform scaling, Pillow bilinear interpolation and centered white padding. A 640 × 480 source becomes 224 × 168 with 28 white rows above and below. No outer spiral turns are cropped.
3. Convert to contiguous float32 `[3, 224, 224]`, divide RGB values by 255, and normalize channels with ImageNet mean `(0.485, 0.456, 0.406)` and standard deviation `(0.229, 0.224, 0.225)`.
4. Apply the same deterministic steps to training, validation and final test. **Augmentation starts disabled**, as specified in the roadmap. There are no learned statistics, colour changes, flips, rotations, thresholding, morphology or denoising in v1.

The source PNGs already contain the time-colour representation. Filtering or binarizing them could discard that cue or fine irregularities, so those methods require separate development experiments. PNG-to-TXT pairing is unverified; this implementation does not reconstruct drawings or infer stroke counts from traces.

Processing happens during reading. No processed-data cache is used and no raw file is overwritten. Every transform has a serializable configuration and SHA-256 fingerprint. Changing any operation requires a new pipeline version; experiments must retain their configuration and environment versions.

## Run B1 without a model

```bash
python -m utils.check_inputs --fold-id 1 --batch-size 8
python validate_data.py
python -m pytest -q
```

`utils/check_inputs.py` iterates all training and validation batches for one development fold, validates shapes/dtypes/finite values/target ranges, checks source SHA-256 hashes and unchanged raw files, checks drawing coverage, and saves a review grid. It never requests a test loader or opens held-out test images.

For a different data location:

```bash
python -m utils.check_inputs --manifest /path/to/fold_manifest.csv --root /path/to/project
```

For loading in background worker processes, add `--num-workers 2`. The default is 0. On macOS, call loaders from a script guarded by `if __name__ == "__main__":` when using workers.

## Dataset and loader interface

```python
from config import PreprocessingConfig
from data.dataloader import make_loader, build_train_transform, build_eval_transform

config = PreprocessingConfig(image_size=224)
train_loader = make_loader(
    fold_id=1, split="train", batch_size=8, seed=42,
    transform=build_train_transform(config),
)
val_loader = make_loader(
    fold_id=1, split="val", batch_size=8,
    transform=build_eval_transform(config), allow_empty=True,
)
batch = next(iter(train_loader))
images, targets = batch["image"], batch["label"]
# images: float32 [B, 3, 224, 224]; targets: int64 [B]
```

Omitting `transform` selects the same versioned v1 pipeline automatically. A custom transform **replaces** the pipeline and must return a finite float32 `[3, image_size, image_size]` tensor; transforms are not applied twice. Supply the matching `image_size` argument to the loader if using a non-default size.

Samples keep the existing `image`, `label`, `label_name`, `drawing_id`, `image_name`, `participant_id`, `subject_key`, `fold_id` and `role` keys. Additional metadata:

| Key | Meaning |
| --- | --- |
| `image_path` | Resolved source PNG path |
| `expert_label` | Expert interpretation, distinct from diagnosis |
| `expert_target` | Control=0, Parkinson=1, Unknown=2; −1 if no finalized expert target in clinical-label mode |
| `clinical_label` | Recorded clinical cohort; not independently verified diagnosis |
| `label_source` | `consensus` or `real`; `label` is the target selected by this option |

Clinical metadata is returned separately for reporting and is not appended to image tensors. Consensus mode retains Unknown as class 2. Missing/unfinalized expert labels are not converted into Unknown.

The loader selects one model fold and requested role, then filters eligibility. Quarantined and unassigned drawings never become model input. It rejects inconsistent partition/fold roles, subject leakage and duplicate-content leakage by group or recorded image hash. Train shuffles with a local seeded generator; validation/test preserve manifest order; workers receive reproducible seeds. No eligible final short batch is dropped.

Fold 22 validation is intentionally empty. Set `allow_empty=True` when requesting it; do not manufacture a validation score. The training entry point already handles it.

## Integration with the existing entry points

`train.py` now explicitly supplies training/evaluation transforms and writes the preprocessing configuration/hash/runtime versions into both checkpoint paths and run history. `eval.py` restores and verifies that recorded configuration. Legacy checkpoints without preprocessing metadata are rejected with a clear message. Model architectures, losses and model-selection rules were not changed.

The entry-point test checks this wiring with a tiny stand-in state dictionary; it does not train or evaluate a research backbone. The only model-facing contract verified here is image/target input, not `[B,3]` model logits.

## Visual review and provenance

Default outputs are under `outputs/preprocessing/`:

| File | Purpose |
| --- | --- |
| `development_review.png` | Original versus inverse-normalized model-input preview |
| `review_selection.json` | Fixed drawing IDs for repeating the same grid |
| `review_grid.json` | Source hashes, selection reasons, dimensions, QC-only flags and transform metadata |
| `b1_report.json` | Batch shapes, counts, labels, data/config hashes and integrity checks |
| `setup_report.json` | Local data setup provenance for this checkout |

Selection is deterministic and development-only. It includes both cohorts, exact duplicate examples, the smallest edge margin, the faintest mean foreground contrast and dense drawings where available. These pixel statistics select examples only; they do not change preprocessing or eligibility. Development duplicate images are visibly marked **quarantined / QC only**. Test duplicates and unassigned identities are excluded before any grid source is opened. Multi-stroke membership is not claimed without verified pairing.

To repeat the same selected examples:

```bash
python -m utils.check_inputs --selection outputs/preprocessing/review_selection.json
```

The grid is prepared for research-team review. Visual inspection does not establish clinical usefulness; no claim of clinical approval or model accuracy is made.

## Verified results in this checkout

- 48 automated tests pass, including a spawned-worker loader, geometry/alpha handling, normalization inversion, invalid input detection, leakage rejection, raw-file preservation, development-only visualization, train/eval configuration handoff and compatibility with the earlier dataset imports.
- Real fold 1: **99 training images / 31 participants; 4 validation images / 1 participant**. Combined: all **103 eligible development images**, with no repeats or dropped images.
- Default output tensors are finite float32 `[B,3,224,224]`; labels are int64 `[B]` with IDs 0–2. Repeated transforms are identical.
- The standard real-data validator passes for the regenerated 147-drawing, 25-fold manifest.

No research model was trained and no held-out test performance was evaluated as part of B1.
